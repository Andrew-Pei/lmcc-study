Transformer 架构

Transformer是现代大语言模型的基石架构，由Google在2017年提出。它摒弃了RNN的递归结构，完全基于注意力机制。

三大架构类型

类型代表模型特点适用场景
编码器 (Encoder)BERT双向注意力，理解上下文分类、NER
解码器 (Decoder)GPT系列单向注意力，自回归生成文本生成
编码器-解码器T5, BART交叉注意力翻译、摘要

核心组件

  • 自注意力机制：允许序列中任意位置直接交互，处理长距离依赖
  • 多头注意力：多组QKV并行计算，捕获不同子空间的信息
  • 前馈神经网络 (FFN)：每个位置独立的两层MLP，增加非线性
  • 残差连接：缓解梯度消失，支持深层网络训练
  • 层归一化 (LayerNorm)：稳定训练，可选Pre-Norm或Post-Norm
  • 位置编码：为无序的注意力机制提供位置信息

数据流向

TextTransformer数据流
输入序列 → 嵌入层 + 位置编码
         ↓
    ┌─────────────────┐
    │  多头自注意力    │ ← Q, K, V 线性投影
    │  (Self-Attention)│
    ├─────────────────┤
    │  Add & LayerNorm │ ← 残差连接 + 归一化
    ├─────────────────┤
    │  前馈网络 (FFN)   │ ← 两层MLP + 激活函数
    ├─────────────────┤
    │  Add & LayerNorm │ ← 残差连接 + 归一化
    └─────────────────┘
         ↓ (重复N层)
      输出 → Linear → Softmax → 概率分布

注意力机制详解

Self-Attention（自注意力）

Query、Key、Value都来自同一个输入序列，通过三个不同的权重矩阵投影得到。

Python自注意力计算
# Q, K, V 都来自输入 x 的不同线性变换
Q = x @ Wq    # (B, L, D) @ (D, D) → (B, L, D)
K = x @ Wk    # 同上
V = x @ Wv    # 同上

# 注意力分数 = Q · K^T / √(dk)
scale = 1.0 / math.sqrt(D)
logits = torch.matmul(Q, K.transpose(-2, -1)) * scale  # (B, L, L)

# 因果掩码（解码器专用）
logits = logits.masked_fill(causal_mask == 0, float('-inf'))

# Softmax 归一化
attn = torch.softmax(logits, dim=-1)  # (B, L, L)

# 加权求和
output = torch.matmul(attn, V)  # (B, L, D)

分组查询注意力 (GQA)

GQA是MHA和MQA的折中方案：查询头数H > 键值头数Kv，通过复制KV头来匹配Q。

类型查询头数KV头数特点
MHA (Multi-Head Attention)HH标准多头注意力
GQA (Grouped-Query)HKv (Kv < H)KV头共享，减少KV Cache
MQA (Multi-Query)H1所有头共享1组KV
PythonGQA中的KV扩展
def expand_kv_for_gqa(x, n_rep):
    """将KV头扩展到与查询头数一致"""
    B, Kv, L, D = x.shape
    H = Kv * n_rep
    x = x.unsqueeze(1).repeat(1, n_rep, 1, 1, 1)
    # (B, n_rep, Kv, L, D) → (B, H, L, D)
    return x.reshape(B, H, L, D)

# 在GQA推理中：
kH = expand_kv_for_gqa(k_all, head_rep)
vH = expand_kv_for_gqa(v_all, head_rep)

缩放因子的作用

注意力分数 Q·K^T 随维度D增大而增大，导致softmax进入饱和区（梯度趋近0）。乘以 1/√D 将方差控制在1附近，保持梯度健康。

LoRA（低秩适配）

LoRA通过在冻结的原始权重旁并联低秩矩阵A和B，只训练A和B，大幅减少训练参数。

PythonLoRA配置
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=8,                    # 低秩矩阵的秩
    lora_alpha=16,          # 缩放因子 (通常 = 2 * r)
    target_modules=["q_proj", "v_proj"],  # 注入位置
    lora_dropout=0.05,     # Dropout
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)
i
LoRA关键参数

r (秩)：低秩矩阵的维度。越大表达能力越强但参数越多。常见值：8, 16, 64
lora_alpha：缩放因子，控制LoRA对原始权重的影响。通常设为2*r
target_modules：注入LoRA的层。最常用：["q_proj", "v_proj"]

RLHF vs DPO

对比项RLHFDPO
流程SFT → 训练奖励模型 → PPO训练SFT → 直接偏好优化
是否需要奖励模型需要不需要
训练稳定性较低（PPO不稳定）较高
实现复杂度高低

学习率预热 (Warmup)

训练初期模型权重随机初始化，梯度较大。直接使用大学习率可能导致梯度爆炸。Warmup在训练前N步使用较小学习率逐步增大到目标值，稳定训练初期。

推理与部署

解码策略

策略原理优点缺点
贪心搜索 (Greedy)每步选概率最高的token速度快可能错过全局最优
束搜索 (Beam Search)维护K条候选路径整体质量更好计算量大
Top-K采样从概率最高的K个中采样增加多样性可能选到低质量token
Top-P (核采样)从累积概率≥P的token中采样自适应选择范围参数敏感

vLLM

vLLM通过PagedAttention机制管理KV Cache内存，解决内存碎片问题，实现高吞吐量推理服务。

i
PagedAttention

借鉴操作系统虚拟内存的分页机制，将KV Cache分成固定大小的"页"，按需分配，避免连续内存分配导致的碎片化。

MoE（混合专家模型）

MoE通过路由机制将不同token分配给不同的"专家"网络，增加模型容量而不等比增加计算量。

!
MoE主要挑战

专家负载不均衡：某些专家被过度使用，其他专家训练不足。需要通过负载均衡损失等机制来缓解。

Embedding 与相似度计算

这是第二轮T2的核心知识。Embedding模型将文本转换为向量，通过向量间的距离衡量语义相似度。

工作流程

TextEmbedding相似度计算流程
文本1 → Tokenize → Embedding模型 → last_hidden_state
                                           ↓
                                    Last-token Pooling
                                           ↓
                                    L2 归一化
                                           ↓
                                    句向量1 (unit vector)

文本2 → Tokenize → Embedding模型 → last_hidden_state
                                           ↓
                                    Last-token Pooling
                                           ↓
                                    L2 归一化
                                           ↓
                                    句向量2 (unit vector)
                                           ↓
                            余弦相似度 = vec1 · vec2 (点积)

Pooling策略对比

策略做法适用模型
Last-token Pooling取序列最后一个有效token因果模型 (GPT, Qwen)
Mean Pooling对所有token求平均双向模型 (BERT)
CLS Token Pooling取第一个token ([CLS])BERT系列

左侧 vs 右侧 Padding

!
Last-token Pooling的Padding方向问题

右侧Padding（默认）：pad_token在右边，最后一个token是padding。需要找到最后一个有效token的位置。
左侧Padding：pad_token在左边，最后一个token是有效的。直接取最后一个即可。

判断方法：检查attention_mask[:, -1].sum() == batch_size，如果为True说明所有样本最后位置都有效（左侧padding）。

L2归一化

PythonL2归一化
import torch.nn.functional as F

# 归一化前：||vec|| 可能是任意长度
# 归一化后：||vec|| = 1

sentence_embeddings = F.normalize(sentence_embeddings, p=2, dim=1)

# 归一化后的点积 = 余弦相似度
similarity = (vec1 @ vec2).item()  # 值域 [-1, 1]

余弦相似度

余弦相似度衡量两个向量方向的夹角，值域[-1, 1]。值越接近1表示越相似，越接近-1表示越相反，0表示正交（不相关）。在文本相似度任务中，值通常在[0, 1]范围内。

提示词工程

这是第二轮T1的核心知识。好的System Prompt能显著提升模型输出的准确性和格式规范性。

Prompt设计原则

1

明确角色

告诉模型它的身份："你是一个精确的数学计算助手"

2

明确规则

定义输入符号的映射规则，让模型理解各种变体

3

明确步骤

要求模型按步骤计算，利用思维链提高准确性

4

明确格式

严格约束输出格式：[Answer]: 数值

Chat Template

Chat Template是Transformers库提供的方法，将对话消息（system/user/assistant）转换为模型能理解的输入文本。

PythonChat Template使用
messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": problem},
]

rendered = tokenizer.apply_chat_template(
    messages,
    tokenize=False,              # 返回文本字符串
    add_generation_prompt=True,  # 添加生成提示符
    enable_thinking=True,        # 启用思考模式 (Qwen3)
)

# rendered 是一个字符串，可以直接传给 model.generate()
i
enable_thinking 参数

Qwen3模型支持思考模式，启用后模型会先在<think>标签中进行推理，然后在</think>后输出最终答案。评测程序会自动移除思考内容，只提取最终答案。

思维链 (Chain-of-Thought)

思维链是指模型在给出最终答案前，先展示推理过程。研究表明这能显著提高复杂推理任务的准确性。

✓
CoT在T1中的应用

在System Prompt中要求模型"分步计算"，配合enable_thinking=True，让模型先推理再输出答案。这能帮助模型正确处理各种符号变体和复杂运算。
